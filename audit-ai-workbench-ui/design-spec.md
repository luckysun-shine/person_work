# 设计探索规范

## 本质需求

这是给审计监察数据分析师每天长时间使用的个人工作台。它需要把项目推进、数据请求、SQL 复用、监测模型维护和周计划放进一个一致的操作环境。视觉必须服务于快速扫描、准确检索和可追溯维护，不能做成展示大屏。

## 受众与场景

- 受众为熟悉 SQL、数据分析和审计业务的单人专业用户。
- 主要在一米距离的桌面显示器上使用，偶尔用手机查看任务或快速记录。
- 高频任务是找回历史 SQL、查看模型运行与变更、处理数据请求和安排本周工作。
- 用户愿意接受较高信息密度，但需要清楚的层级、稳定的定位感和低疲劳配色。

## 共同内容

三个完整版必须使用相同的信息和数据，只允许改变视觉系统、版式骨架和交互表达。

### 首页工作台

- 今日待办 5 项，本周完成 12 项，等待他人 3 项。
- 重点项目包括采购异常监测模型、审计报告数据支撑和制度知识库。
- 最近数据请求包括固定资产盘点差异、采购付款明细和供应商关联分析。
- 常用入口包括审计系统、数据仓库、BI 平台、法规库和知识库。

### SQL 查询库

- 支持关键词搜索、项目筛选、标签筛选和状态筛选。
- 列表展示 SQL 名称、用途、涉及表、项目、版本、最近更新和复用次数。
- 示例资产包括采购付款异常明细、固定资产处置审批链、供应商关联交易识别和模型结果汇总。

### SQL 详情

- 展示用途说明、参数、涉及表、SQL 正文、版本记录、关联数据请求和注意事项。
- SQL 正文使用语法高亮，代码只是展示，不执行。
- 需要明显区分正式字段与 AI 生成的逻辑摘要。

### 监测模型详情

- 展示模型规则、当前版本、运行状态、运行频率、最近结果、依赖对象和更新步骤。
- 更新步骤包括更新前检查、修改、发布、验证和回滚。
- 支持勾选步骤、切换版本记录和查看关联 SQL。

## 输出范围

- 六候选缩略图总览一份，画布宽 1440 像素。
- 三个完整单文件 HTML，每个包含四个可切换代表页面。
- 每个方向提供 1440 x 900 截图和完整页面截图。
- 当前回合只交付方向稿，不进入最终 UI 系统和生产代码。

## 共同约束

- 中文正文不小于 14 像素，主要正文采用 16 至 17 像素。
- 可点击区域不小于 44 x 44 像素。
- 正文对比度至少达到 4.5 比 1。
- 数据数字使用等宽数字特性。
- 不使用紫色全屏渐变、Emoji 导航、装饰性指标卡和虚构用户评价。
- 不保存真实密码、令牌、数据库连接串或审计敏感信息。
- 不以卡片数量制造丰富感，结构件必须表达业务关系。

## 共同交互

- 左侧导航可切换四个页面。
- 全局搜索框可获得焦点并展示搜索提示。
- SQL 列表行可选中并进入 SQL 详情。
- SQL 详情支持切换版本和复制代码反馈。
- 模型详情支持切换概览、依赖、更新步骤和版本记录。
- 首页任务支持勾选完成并更新状态。

## 五问答案

- 叙事角色：操作型数据工作台，首页负责定向，详情页负责证据与执行。
- 观众距离：一米笔记本或显示器，优先桌面信息密度。
- 视觉温度：冷静、准确、可信，允许一个方向更大胆，但不能娱乐化。
- 容量估算：首页同时容纳任务、项目、请求和入口；列表页每屏至少显示六条记录；详情页代码与元数据并存。
- 视觉母题：SQL 语句、模型依赖和版本变更形成的可追溯链条，是其他普通待办工具没有的内容结构。
